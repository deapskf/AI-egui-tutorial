第一部分：入门篇

﻿# 04 · 开发工作流与项目结构

前两章我们写了简单的计数器应用，所有代码都在 main.rs 中。随着项目增长，你需要组织代码结构、优化编译配置、使用效率工具。本章覆盖 egui 开发的实践知识。

4.1 推荐的 Cargo.toml 配置

最小配置

[package]
name = "my-egui-app"
version = "0.1.0"
edition = "2024"

[dependencies]
eframe = "0.34"

选择渲染后端

egui 0.34 起，wgpu 是默认渲染器。如果你想使用 OpenGL（如兼容老显卡或特定平台需求）： 
# 使用 OpenGL (glow) 后端
eframe = { version = "0.34", default-features = false, features = ["glow"] }
后端Feature底层适合
wgpu（默认）default-featuresVulkan / Metal / DX12 / WebGPU现代平台
glowfeatures = ["glow"]OpenGL 3.3+ / WebGL兼容性优先

对初学者来说，保持默认（wgpu）即可。只有在默认后端出问题时才考虑切换。

Release 构建优化

在 Cargo.toml 末尾添加 profile 配置： 
[profile.release]
opt-level = 3      # 最高优化级别
lto = "fat"        # 链接时优化（略微增加编译时间）
codegen-units = 1  # 单代码生成单元（更好的优化，略慢编译）
strip = true       # 移除调试符号（减小文件体积）
这能将 .exe 文件从 ~20MB 减小到 ~5MB，启动速度也更快。

4.2 典型项目目录结构

随着功能增多，单文件 main.rs 会变得难以维护。推荐的演进路径是：

小型项目（< 500 行）

my-app/
├── Cargo.toml
└── src/
    └── main.rs          # 包含 MyApp + logic + ui

中型项目（500 ~ 2000 行）

my-app/
├── Cargo.toml
└── src/
    ├── main.rs          # main 函数 + NativeOptions 配置
    └── app.rs           # MyApp 结构体 + App trait 实现
src/main.rs： 
mod app;

use app::MyApp;

fn main() -> eframe::Result<()> {
    let native_options = eframe::NativeOptions::default();
    eframe::run_native(
        "我的应用",
        native_options,
        Box::new(|_cc| Ok(Box::new(MyApp::default()))),
    )
}
src/app.rs： 
use eframe::egui;

pub struct MyApp {
    // 你的状态字段...
}

impl Default for MyApp {
    fn default() -> Self { / ... / }
}

impl eframe::App for MyApp {
    fn logic(&mut self, ctx: &egui::Context, frame: &mut eframe::Frame) {
        // ...
    }
    fn ui(&mut self, ui: &mut egui::Ui, _frame: &mut eframe::Frame) {
        // ...
    }
}

大型项目（> 2000 行）

my-app/
├── Cargo.toml
└── src/
    ├── main.rs
    ├── app.rs           # MyApp 结构体
    ├── panels/          # 按界面区域拆分
    │   ├── mod.rs
    │   ├── sidebar.rs
    │   ├── content.rs
    │   └── status_bar.rs
    ├── widgets/         # 自定义 Widget
    │   ├── mod.rs
    │   └── color_picker.rs
    └── utils/           # 工具函数
        ├── mod.rs
        └── theme.rs

4.3 开发效率工具

cargo watch 自动重编译

安装 cargo-watch： 
cargo install cargo-watch
然后替代 cargo run 使用： 
cargo watch -x run
每次保存文件，自动重新编译和运行。对于 UI 开发——频繁小修改、立即看效果——非常实用。

环境变量与日志

egui 使用 log crate 输出内部日志。启动应用时设置环境变量： 
# PowerShell (Windows)
$env:RUST_LOG = "debug"
cargo run


bash (Linux/macOS)

RUST_LOG=debug cargo run
egui 会输出纹理加载、字体图集更新、帧时间等调试信息。 如果你使用 log crate 在自己的代码中打印日志，配合 env_logger： 
[dependencies]
eframe = "0.34"
log = "0.4"
env_logger = "0.11"

fn main() {
    env_logger::init(); // 初始化日志系统
    log::info!("应用启动");
    // ...
}

eframe::NativeOptions 调试开关

let native_options = eframe::NativeOptions {
    follow_system_theme: false,  // 不跟随系统主题（方便调试自定义主题）
    vsync: true,                  // 垂直同步（默认 true，一般保留）
    renderer: eframe::Renderer::Wgpu, // 显式指定渲染器
    ..Default::default()
};
字段说明
follow_system_theme是否跟随系统明/暗主题
vsync垂直同步（减少撕裂，但可能有轻微延迟）
rendererRenderer::Wgpu / Renderer::Glow
viewport自定义窗口大小、位置等（详见第 35 章）
depth_buffer深度缓冲位数（3D 内容需要）
multisamplingMSAA 抗锯齿采样数

4.4 跨平台注意事项

egui 的代码在 Windows、macOS、Linux 上几乎完全一致。以下是你需要知道的主要区别：

路径差异

// ❌ 不要硬编码路径分隔符
let path = "data\\config.json";  // Windows 特有

// ✅ 使用 std::path::Path
let path = std::path::Path::new("data").join("config.json");

文件对话框

rfd（Rust File Dialog）crate 在各平台调用原生文件选择对话框（第 30 章会详细讲解）。

字体配置

  • Windows：系统字体在 C:\Windows\Fonts\
  • macOS：系统字体在 /System/Library/Fonts/ 和 /Library/Fonts/
  • Linux：系统字体在 /usr/share/fonts/
推荐的方式是将字体文件通过 include_bytes! 嵌入应用，确保跨平台一致性（第 22 章）。

窗口行为

  • Windows：窗口行为最标准
  • macOS：菜单栏在屏幕顶部，不是窗口内部
  • Linux：不同桌面环境有细微差异
egui 为你处理了大部分差异，你通常不需要写平台特定代码。
